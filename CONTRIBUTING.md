# Как развивать проект

Проект учебный и открытый: его можно скачать, запустить, менять и предлагать изменения. Здесь — как он устроен и как сделать свою задачу так, чтобы ничего не сломать.

## Учебный режим

В `backend/.env` по умолчанию `DEMO_MODE=true`: всё, для чего нужны ключи, имитируется, но работает тот же код, что с настоящими сервисами.

| Что | Как имитируется | Где смотреть |
|---|---|---|
| Код входа (SMS / Telegram) | Код показывается прямо на странице входа и подставляется сам | Витрина → «Войти» |
| Оплата Payme и Click | Страница «Учебная оплата» отправляет магазину те же запросы, что настоящий провайдер (`payments/demo.py`) | Заказ → «Оплатить через …» |
| Telegram-бот | Сообщения бота пишутся в базу; можно нажимать кнопки и отвечать от имени поставщика, покупателя, менеджера | Админка → «Имитация Telegram» |

Настоящий ключ в `.env` всегда главнее имитации. Учебный режим — не для настоящего магазина: в нём любой может «оплатить» заказ.

## Как устроен проект

```
backend/apps/
  catalog/        товары, характеристики, совместимость аксессуаров, поиск
  sourcing/       поставщики, прайсы (CSV/Excel/API), сопоставление, предложения, резервы
  inventory/      свой склад поштучно: устройства с IMEI
  pricing/        курс ЦБ, наценки, цена в сумах
  promo/          подарки: бюджет от маржи
  customers/      покупатели, вход по коду
  orders/         корзина, заказ, машина состояний (state.py), сборка, возвраты, рабочее место оператора
  payments/       Payme и Click: протоколы, ссылки на оплату, учебная имитация
  delivery/       передача в доставку: свой курьер или служба
  warranty/       гарантийные случаи по IMEI
  notifications/  outbox (надёжная доставка событий) и клиент Telegram
  bot/            Telegram-бот: команды, кнопки поставщиков, имитация
  core/           фоновые задачи (run_jobs), демо-данные (seed_demo), лимиты запросов
frontend/src/
  app/[lang]/     страницы витрины на русском и узбекском
  components/     части страниц
  lib/            запросы к API (схемы zod), корзина, тексты ru/uz (i18n.ts)
e2e/              проверка витрины в настоящем браузере
docs/superpowers/ спецификация и планы — почему сделано именно так
```

Хорошая точка входа: `docs/superpowers/specs/…-design.md` (что и зачем), потом планы по порядку — каждый описывает одну большую часть.

## Как сделать задачу

1. Ветка: `git checkout -b feat/korotkoe-nazvanie`.
2. **Сначала тест.** Напишите тест на то, что должно появиться, и убедитесь, что он падает. Тесты бэкенда — рядом с кодом в `apps/*/tests/`, фронтенда — `src/lib/*.test.ts`.
3. Код, пока тест не станет зелёным.
4. Все проверки:
   ```
   cd backend && .venv\Scripts\python.exe -m pytest
   cd frontend && npm run lint && npm test && npm run build && npx tsc --noEmit
   ```
5. Коммит в формате `тип: что сделано` — типы `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`. Например: `feat: add installment calculator`.
6. Pull request: что сделано, как проверить. GitHub сам прогонит тесты.

## Правила, которые держат проект целым

- **Статус заказа** меняется только через `orders.services.transition` — там проверка по таблице `orders/state.py` под блокировкой строки.
- **Деньги**: суммы в сумах — целые числа, себестоимость в $ — `Decimal`. Никаких `float`.
- **Внешние сервисы** — только через outbox (`notifications.outbox.emit`) или за функцией, которую легко подменить в тесте.
- **Данные извне** проверяются: на бэкенде — сериализаторами DRF, на фронтенде — схемами zod в `lib/schemas.ts`.
- **Секреты** — только в `backend/.env` и `frontend/.env.local`, никогда в коде и в git.
- **Тексты для покупателя** — на двух языках: `frontend/src/lib/i18n.ts`, `backend/apps/bot/texts.py`.

## Идеи задач

Попроще:
- Загрузка прайса поставщика файлом прямо в админке (сейчас — командой `import_feed_file` или в бот).
- Отправка файла прайса в «Имитации Telegram».
- Тёмная тема витрины.
- Отзывы о товаре с модерацией в админке.

Посложнее:
- Рассрочка (Uzum Nasiya / Alif) с учебной имитацией, как у Payme и Click: калькулятор 3/6/12 месяцев на карточке, заявка, подписание.
- Карта при вводе адреса (OpenStreetMap + Leaflet — без ключа).
- Возврат, оформленный самим покупателем в «Моих заказах».
- Telegram Mini App для витрины.
- Нагрузочный тест (k6): сколько заказов в минуту выдерживает сервер.
