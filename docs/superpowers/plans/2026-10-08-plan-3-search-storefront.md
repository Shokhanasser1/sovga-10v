# План 3. Поиск и витрина — план реализации

> Выполняется по задачам, каждая через TDD: тест → падает → код → проходит → коммит.

**Goal:** Покупатель находит товар поиском с автокомплитом (опечатки, кириллица/латиница, «айфон» → iPhone), фильтрует каталог по фасетам и цене, открывает карточку с выбором варианта, ценой, наличием и подарком, сравнивает модели — на русском и узбекском.

**Architecture:** Поиск — в базе, без Meilisearch: у модели товара хранится нормализованный транслитерированный `search_text`, запрос нормализуется так же, раскрываются синонимы из админки, совпадение по началу слов; если пусто — нечёткий поиск (difflib). Для листинга у модели товара есть кэш `price_from_uzs` и `is_available`, его обновляет `run_jobs`. Витрина — Next.js (App Router, TypeScript), серверная отрисовка страниц, данные из DRF API.

**Tech Stack:** Django/DRF (как раньше); Next.js + React + TypeScript; Playwright (Python) для e2e.

## Global Constraints

Все ограничения Планов 1–2 действуют. Дополнительно:
- Никаких отдельных поисковых сервисов: поиск работает на SQLite и PostgreSQL одинаково.
- Нормализация одна для индекса и запроса: нижний регистр, кириллица → латиница, без апострофов узбекской латиницы, буквы и цифры разделяются («iphone15» → «iphone 15»).
- Коды атрибутов в фильтрах принимаются только из определений категории.
- Витрина не получает себестоимость, источники и фискальные коды.
- Языки витрины: `ru` (по умолчанию) и `uz`, префикс в URL: `/ru/...`, `/uz/...`.

## Бэкенд

### Task 1. Нормализация и синонимы (`catalog/search_text.py`, модель `SearchSynonym`)
- `transliterate(text)`, `normalize(text)`, `tokens(text)`, `expand_synonyms(tokens, synonyms)`.
- `SearchSynonym(term, replacement)` — хранится в нормализованном виде; стартовый набор миграцией данных (айфон, айпон, галакси, сяоми, хуавей, макс, чехол, зарядка и др.).
- Тесты: транслитерация русского и узбекской кириллицы, разделение букв и цифр, «256 ГБ» = «256gb», синонимы, в том числе многословные.

### Task 2. Поиск и автокомплит (`catalog/search.py`)
- Поле `ProductModel.search_text` (название ru/uz, бренд, цепочка категорий), пересчёт в `save()` и командой `rebuild_search_index`.
- `search_products(query, queryset=None) -> list[ProductModel]` — совпадение всех слов по началу, ранжирование; при пустом результате — нечёткий поиск.
- `suggest(query) -> {"products": [...до 8], "categories": [...до 3]}`; `GET /api/v1/catalog/search/suggest/?q=`.
- Тесты: «айфон 16», «aypon», «самсунг галакси», «iphone15», опечатка «iphnoe», черновики не находятся, пустой запрос.

### Task 3. Кэш листинга (`ProductModel.price_from_uzs`, `is_available`)
- `pricing/listing.py`: `refresh_listing_cache(now) -> int` — минимальная цена среди доступных вариантов (если доступных нет — среди всех с ценой), доступность = хоть один вариант «в наличии» или «под заказ». Вызов в `run_jobs` вместе с `rebuild_search_index`.
- Тесты: цена «от», товар без цен, недоступный товар, `run_jobs` обновляет кэш.

### Task 4. Фильтры, сортировка, фасеты
- `GET /api/v1/catalog/products/` принимает `q`, `category`, `brand` (через запятую), `f.<код>=v1,v2`, `price_min`, `price_max`, `available=1`, `sort=relevance|price_asc|price_desc|name`; в ответе `price_from_uzs`, `is_available`.
- `GET /api/v1/catalog/facets/?category=&q=` → бренды, атрибуты-фасеты со счётчиками, диапазон цен.
- Тесты: фильтр по атрибуту модели и по оси варианта, приведение типов, неизвестный код игнорируется, цена и наличие, сортировки, счётчики фасетов.

## Витрина (`frontend/`)

### Task 5. Каркас Next.js
- Next.js (App Router, TypeScript), `src/lib/api.ts` — типизированный клиент к API (адрес из `NEXT_PUBLIC_API_URL`), словари `ru`/`uz`, общий макет (шапка с поиском, переключатель языка), форматирование сумм.
- Проверка: `npm run build` без ошибок, unit-тесты форматирования цены и выбора языка.

### Task 6. Каталог и поиск
- `/[lang]/catalog/[category]` и `/[lang]/search?q=` — сетка товаров (цена «от», наличие), фасеты, сортировка, пагинация; автокомплит в шапке.

### Task 7. Карточка товара
- `/[lang]/product/[slug]` — матрица вариантов (недоступные — серые), цена, наличие, «подарок до X сум», характеристики, совместимые аксессуары, кнопка «Сравнить».

### Task 8. Сравнение
- `/[lang]/compare?skus=` — таблица с подсветкой лучших значений; выбор моделей хранится в `localStorage`.

### Task 9. E2E-проверка
- Скрипт Playwright (Python): поиск «айфон» → карточка → выбор варианта → сравнение; переключение на `uz`. Данные — команда `seed_demo` (демо-каталог).
