# План 5. Возвраты, гарантия по IMEI, выгрузка для бухгалтера — план реализации

> Выполняется по задачам, каждая через TDD: тест → падает → код → проходит → коммит.

**Goal:** Оператор оформляет возврат доставленного заказа, принимает его со сверкой IMEI и отмечает возврат денег; открывает гарантийный случай по IMEI и видит дату покупки, срок гарантии и поставщика; бухгалтер получает Excel с реализациями и возвратами за период; покупатель видит IMEI и срок гарантии на странице заказа.

**Architecture:** Возвраты — `orders/returns.py` и модель `ReturnRequest` (машина состояний: DELIVERED/COMPLETED → RETURN_REQUESTED → INSPECTED → REFUNDED, отказ → COMPLETED). Гарантия — приложение `warranty`: `WarrantyCase` на устройство, срок — `Category.warranty_months`. Выгрузка — `orders/reports.py` (openpyxl, уже в зависимостях). Всё для сотрудников — в той же админке: рабочее место оператора (возвраты, поиск заказа), «Гарантия», «Выгрузка для бухгалтера».

**Спецификация:** раздел 5.2 («Возвраты и гарантия», «Подарок»), раздел 1 (выгрузка реализаций), раздел 6 P0 (личный кабинет: гарантия по IMEI).

## Global Constraints

Все ограничения Планов 1–4d действуют. Дополнительно:
- Срок возврата товара надлежащего качества — `RETURN_DAYS` (по умолчанию 10 дней с доставки; точный срок — вопрос юристу из фазы 0). После срока доставленный заказ сам становится «Завершён» (`run_jobs`).
- Приёмка возврата: IMEI принесённых устройств должны совпасть с проданными по заказу — иначе отказ (спецификация). Подарок не вернули — из суммы возврата удерживается его цена на момент заказа (`OrderLine.gift_value_uzs`).
- Деньги возвращает человек в кабинете Payme / Click; система фиксирует сумму и момент. Возвращённые устройства — статус «Возвращён», в продажу сами не попадают.
- Гарантийный случай — только для проданного устройства и только в срок гарантии.
- Выгрузка: реализация — по дате передачи в доставку, возврат — по дате возврата денег; суммы в сумах, НДС выделен (12 %, `FISCAL_VAT_PERCENT`), себестоимость в $ и сумах по курсу заказа.
- Названия товаров для людей (оператор, поставщик, бухгалтер) — «iPhone 15 · 128 ГБ · Чёрный», не внутренние коды.

## Задачи

### Task 1. Названия модификаций для людей
- `catalog/labels.py`: `variant_title(variant)`; заменить в сборке, рабочем месте и сообщениях поставщикам (сопоставление прайсов не трогаем).

### Task 2. Возвраты
- `OrderLine.gift_value_uzs`; `ReturnRequest(order, reason, status, imeis_received, gift_returned, refund_amount_uzs, note, created_at, inspected_at, refunded_at)`.
- `open_return`, `inspect_return` (сверка IMEI), `reject_return`, `refund_return`, `complete_delivered` (в `run_jobs`).
- Рабочее место: поиск заказа по номеру или телефону, раздел «Возвраты», формы на странице заказа. Покупателю — статусы в Telegram с суммой.
- Тесты: срок возврата, сверка IMEI, удержание подарка, отказ, повторные действия, автозавершение.

### Task 3. Гарантия по IMEI
- `Category.warranty_months` (12); `warranty.WarrantyCase(unit, complaint, service_center, status, note, opened_at, closed_at)`.
- Админка «Гарантия»: «Открыть по IMEI» — карточка устройства (покупатель, заказ, дата продажи, гарантия до, поставщик, прошлые случаи) и форма; статусы случая.
- В заказе на сайте: IMEI и «гарантия до» у проданных устройств.
- Тесты: поиск по IMEI1/IMEI2, не проданное, истёкшая гарантия, права.

### Task 4. Выгрузка для бухгалтера
- Админка «Выгрузка для бухгалтера»: период → Excel (листы «Реализации», «Возвраты»).
- Тесты: строки и суммы, НДС, период, подарок с нулевой ценой, права.

### Task 5. Витрина и проверка
- Страница заказа: IMEI и гарантия. Полные тесты, e2e витрины, живая проверка возврата и выгрузки.
