# План 4c. Telegram-бот — план реализации

> Выполняется по задачам, каждая через TDD: тест → падает → код → проходит → коммит.

**Goal:** Поставщик без API подтверждает заказ в боте кнопками «Есть / Нет / Другая цена» — заказ сам переходит в «Ждёт оплаты» или отменяется; покупатель получает статусы заказа в Telegram; менеджеры — алерты, если поставщик молчит, отказал или поднял цену.

**Architecture:** Приложение `bot`: одноразовые коды привязки чата (`TelegramLink`), разбор входящих обновлений (`dispatch.handle_update`) и команда `manage.py run_bot` — long polling (`getUpdates`), без вебхука, домена и HTTPS. Запросы поставщикам — модель `SupplierRequest` в `orders` (это часть жизненного цикла заказа; подтверждать их может и менеджер в админке). Все исходящие сообщения — через outbox, поэтому сбой Telegram не теряет уведомление.

**Спецификация:** раздел 3.3 («Telegram-бот»), раздел 5.2 («Момент оплаты» — подтверждение поставщика, ссылка на оплату в бот).

## Global Constraints

Все ограничения Планов 1–4b действуют. Дополнительно:
- Токен — только `TELEGRAM_BOT_TOKEN` из окружения (`backend/.env`); старый токен из чата скомпрометирован и не используется. Без токена бот не запускается, уведомления пишутся в лог.
- Текст ошибки сети содержит адрес с токеном — наружу и в лог только тип ошибки.
- Сообщения — простым текстом (без `parse_mode`), чтобы названия товаров и ввод пользователей не ломали разметку.
- Привязка чата — только по одноразовому коду (`secrets`, ≥ 96 бит, срок 24 ч); код покупателю выдаёт вошедший покупатель, поставщику — менеджер в админке.
- Ответ поставщика принимается, только если он пришёл из чата, привязанного к этому поставщику, и заказ всё ещё ждёт подтверждения (проверка под блокировкой).
- Одно обновление с ошибкой не останавливает бота: ошибка в лог, пользователю — общее «Не получилось, попробуйте ещё раз».

## Задачи

### Task 1. Клиент Bot API и привязка чатов
- `notifications/telegram.py`: общий `call(method, payload)`; `send_message` возвращает `message_id`, принимает `reply_markup`.
- `bot.TelegramLink(code, kind customer|supplier, customer, supplier, expires_at, used_at)`; `Supplier.telegram_chat_id`.
- `POST /api/v1/bot/link/ {lang}` → `{url: https://t.me/<TELEGRAM_BOT_USERNAME>?start=c_<code>}` (вошедший покупатель, CSRF); 503 без настроек бота. В заказе — `telegram: linked | available | off`.
- Админка поставщика: действие «Ссылка для подключения бота».
- Тесты: код одноразовый и истекает; чужой/анонимный — 401/403; язык покупателя сохраняется.

### Task 2. Диспетчер и `run_bot`
- `/start c_<code>` / `/start s_<code>` — привязка (чат покупателя отвязывается от прежнего профиля); `/orders` — последние 5 заказов; `/stop` — отписка; `/id` — номер чата (для `MANAGER_CHAT_IDS`); прочее — подсказка.
- `run_bot`: `getUpdates` с `timeout=25`, смещение после обработки, пауза с ростом при сетевых ошибках.
- Тесты: каждая команда, просроченный/использованный код, ошибка в обработчике не роняет цикл.

### Task 3. Запросы поставщикам
- `SupplierRequest(order, supplier, status pending|confirmed|declined|price_offered|awaiting_price, proposed_cost_usd, message_id, sent_at, answered_at, alerted_at)`, уникально `(order, supplier)`.
- Заказ ушёл в SOURCING → по запросу на каждого поставщика его строк → событие `sourcing.requested` → сообщение с кнопками (у поставщика без бота — алерт менеджерам «подтвердите вручную»).
- «Есть» → когда подтвердили все поставщики заказа — `confirm_sourcing`; «Нет» → заказ отменяется, предложение поставщика обнуляется, менеджерам алерт; «Другая цена» → бот ждёт число в $ → менеджерам алерт, заказ ждёт решения в админке.
- `run_jobs`: поставщик молчит 30 минут — один алерт менеджерам.
- Тесты: все ответы, чужой чат, повторное нажатие, заказ уже отменён, неверная цена, алерт один раз.

### Task 4. Статусы покупателю
- `transition` пишет в outbox `order.status`; покупателю с привязанным чатом — сообщение на его языке со ссылкой на заказ. Не шлём технические шаги (начало оплаты и возврат к «Ждёт оплаты» после брошенной оплаты).
- Тесты: тексты ru/uz, подтверждение поставщика → «можно оплатить» со ссылкой, без чата — ничего.

### Task 5. Витрина и запуск
- Страница заказа: «Получать статусы в Telegram», если бот настроен и чат не привязан.
- `.env.example`: `TELEGRAM_BOT_USERNAME`; инструкция запуска `run_bot`.
- Полные тесты бэкенда и фронтенда, e2e витрины.

IMEI от поставщика через бот — в Плане 4d вместе с правилом «без IMEI не отгружаем».
