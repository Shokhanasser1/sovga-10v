# План 4a. Вход по коду, корзина с подарком, оформление заказа — план реализации

> Выполняется по задачам, каждая через TDD: тест → падает → код → проходит → коммит.

**Goal:** Покупатель кладёт товары в корзину, выбирает подарок в пределах бюджета, входит по коду из Telegram/SMS и оформляет заказ; товар резервируется, цена фиксируется, заказ проходит по машине состояний, события надёжно доставляются через outbox.

**Architecture:** Новые приложения `customers` (покупатель = пользователь Django без пароля, OTP), `orders` (заказ, строки, история, машина состояний, расчёт корзины), `notifications` (outbox). Корзина хранится в браузере (localStorage) до оформления — гостевая корзина «сливается» после входа сама собой. Сессия Django в httpOnly-cookie; браузер ходит в API напрямую с `credentials: include`, CSRF-токен — из cookie `csrftoken`.

**Tech Stack:** как в Планах 1–3. Внешние сервисы (Telegram Gateway, Eskiz, Telegram Bot API) — за интерфейсами, в тестах подменяются.

**Спецификация:** раздел 5 (жизненный цикл заказа), раздел 3.2 (резервы), раздел 4 (outbox, вход по телефону).

## Global Constraints

Все ограничения Планов 1–3 действуют. Дополнительно:
- Телефон — только узбекский мобильный, хранится как `+998XXXXXXXXX`.
- Код входа: 6 цифр, живёт 5 минут, повторная отправка не раньше чем через 60 секунд, не больше 5 кодов в час на номер, не больше 5 попыток ввода на код; хранится только HMAC-хэш.
- Фиксированный код для e2e (`OTP_FIXED_CODE`) разрешён только при `DEBUG=true`, иначе запуск падает.
- Без настроенной отправки кодов (`TELEGRAM_GATEWAY_TOKEN` или `ESKIZ_EMAIL`/`ESKIZ_PASSWORD`) в проде запуск падает; при `DEBUG=true` код пишется в лог.
- В корзине до 10 позиций, до 5 штук каждой. Подарок — по штуке на каждую единицу основного товара, только со своего склада, совместимый, дешевле бюджета.
- Способ оплаты при оформлении пока только `card` (рассрочка и оплата при получении — в следующих планах).
- Цена фиксируется на 30 минут с подтверждения заказа; заказ у поставщика без ответа 2 часа отменяется.
- Все изменения статуса — только через машину состояний; каждое пишется в историю и в outbox в той же транзакции.

## Задачи

### Task 1. Покупатели и коды входа (`customers`)
- `normalize_uz_phone(raw) -> str | None`; модели `Customer(user, phone, name, language, telegram_chat_id)`, `Address`, `OtpCode`.
- `request_code(phone, now, sender, ip)`, `verify_code(phone, code, now)`, `OtpError(message, code)`.
- Отправители: `TelegramGatewaySender`, `EskizSmsSender`, `FallbackSender`, `ConsoleSender`; `build_sender()`.
- Тесты: форматы номера; повтор раньше минуты; лимит в час; истечение; 5 неверных попыток; повторное использование кода; падение Telegram → SMS; запросы адаптеров.

### Task 2. API входа
- `GET /api/v1/auth/me/` (ставит CSRF-cookie), `POST /api/v1/auth/request-code/`, `POST /api/v1/auth/verify/`, `POST /api/v1/auth/logout/`; лимит `otp` на посетителя.
- CORS с cookie, `CSRF_TRUSTED_ORIGINS`; запрет `OTP_FIXED_CODE` вне DEBUG.
- Тесты: полный вход; CSRF обязателен; неверный код; создание покупателя при первом входе; выход.

### Task 3. Outbox (`notifications`)
- `OutboxEvent`, `emit(type, payload)`, `register(type)`, `deliver_pending(now)` с повторами (1, 5, 15, 60 мин, 3 ч, 6 ч → «failed»).
- Обработчик `order.created` → сообщение менеджерам в Telegram (если задан `TELEGRAM_BOT_TOKEN` и `MANAGER_CHAT_IDS`).
- Тесты: событие не теряется при откате транзакции заказа; повторы и отказ; неизвестный тип.

### Task 4. Заказ и машина состояний (`orders`)
- Модели `Order`, `OrderLine`, `OrderEvent`; `state.py`: `TRANSITIONS`, `can_transition`, `CANCELLABLE`.
- Тесты: разрешённые и запрещённые переходы, отмена только до отгрузки.

### Task 5. Расчёт корзины с подарками (`orders/quote.py`)
- `quote(items, payment_method, now) -> Quote`: цены, доступность, бюджет подарка, варианты подарка, проверка выбранного подарка, итог.
- Тесты: итог; нет цены / нет в наличии; бюджет подарка и список вариантов; дорогой или несовместимый подарок отклоняется; подарок с чужого склада не предлагается.

### Task 6. Оформление и жизненный цикл (`orders/services.py`)
- `create_order(...)` (резервы, статус SOURCING или CONFIRMED, фиксация цены, история, outbox), `transition(...)`, `confirm_sourcing(...)`, `cancel_order(...)`, `expire_orders(now)`; вызов в `run_jobs`.
- Тесты: свой склад → CONFIRMED; поставщик без API → SOURCING; резервы основного товара и подарка; отмена снимает резервы; просрочка оплаты и молчание поставщика отменяют заказ.

### Task 7. API заказов и админка
- `POST /api/v1/orders/quote/`, `POST /api/v1/orders/`, `GET /api/v1/orders/`, `GET /api/v1/orders/<number>/`, `POST /api/v1/orders/<number>/cancel/`.
- Админка: покупатели, коды (только чтение), заказы со строками и историей, действия «Подтвердить у поставщика» и «Отменить», outbox с повтором.
- Тесты: чужой заказ — 404; без входа — 403; CSRF; валидация; админ-действия.

### Task 8. Витрина: корзина
- `cart-store.ts`, кнопка «В корзину» на карточке, счётчик в шапке, страница `/[lang]/cart` с расчётом, количеством и выбором подарка.

### Task 9. Витрина: вход, оформление, заказ
- `/[lang]/login`, `/[lang]/checkout`, `/[lang]/orders/[number]`, `/[lang]/orders`; клиент с CSRF и cookie.

### Task 10. Сквозная проверка
- e2e: карточка → корзина → подарок → вход по коду → оформление → страница заказа → отмена.
