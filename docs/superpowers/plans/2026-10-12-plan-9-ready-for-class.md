# План 9. Магазин готов к уроку — план реализации

> Выполняется по задачам, каждая через TDD: тест → падает → код → проходит → коммит.

**Goal:** Учитель запускает `scripts\setup.cmd` один раз, перед уроком — `scripts\reset-demo.cmd`, на уроке — `scripts\start.cmd`, и всё работает без ключей и без ручной настройки: витрина, все сотрудники со своими правами (администратор, менеджер, оператор, бухгалтер), оплата картой и при получении, «Имитация Telegram» с правильными датами, сценарий урока под рукой.

## Global Constraints

Все ограничения Планов 1–8 действуют. Дополнительно:
- Пароли сотрудников не попадают в git: они генерируются случайно и пишутся в `backend\demo-accounts.txt` (в `.gitignore`). При пересоздании базы пароли из файла сохраняются — учителю не нужно запоминать новые.
- Учётные записи сотрудников создаются только в учебном режиме; роли (группы с правами) — в любом режиме, они нужны и настоящему магазину.
- Оплата при получении включается `COD_ENABLED` (по умолчанию — как `DEMO_MODE`): настоящему магазину она нужна только при фискальном чеке от службы доставки (спецификация, раздел 5).
- Машина состояний не меняется: CONFIRMED → COD → PICKING.

## Задачи

### Task 1. Оплата при получении — заказ
- Оформление и расчёт принимают `payment_method=cod`, если `COD_ENABLED`; иначе — понятная ошибка. Расчёт корзины и подарок — как при оплате картой.
- Товар подтверждён (свой склад или ответ поставщика) — заказ сам переходит в «Оплата при получении», товар держится 7 дней, как у оплаченного.
- Покупатель может отменить такой заказ до начала сборки.
- Менеджерам — «можно собирать», покупателю — сколько приготовить курьеру; «Ждёт оплаты» такому покупателю не пишем.
- Рабочее место оператора: этап «К сборке»; в очереди и при доставке видно, сколько взять с покупателя; доставка записывает «оплата получена».
- Возврат денег по такому заказу — «наличными или переводом», а не «в кабинете Payme / Click».

### Task 2. Оплата при получении — витрина
- Оформление: выбор «Картой онлайн» / «При получении» (если магазин её принимает — сервер сообщает в расчёте корзины).
- Страница заказа: сумма к оплате курьеру; кнопки оплаты нет, отменить можно.
- e2e: заказ с оплатой при получении и его отмена.

### Task 3. «Имитация Telegram»: даты истории
- Сообщения бота по учебной истории получают время своего события, а не время запуска `seed_demo`; переписка идёт по порядку.

### Task 4. История: заказы с оплатой при получении
- В учебной истории есть заказы с оплатой при получении: доставленный, у курьера и ждущий сборки.

### Task 5. Сотрудники
- Роли: «Менеджер» (каталог, цены, поставщики, склад, заказы, гарантия, отчёт, «Имитация Telegram»), «Оператор» (рабочее место оператора, заказы, возвраты, гарантия, «Имитация Telegram»), «Бухгалтер» (выгрузка для бухгалтера, заказы и платежи — только просмотр).
- `seed_demo` в учебном режиме создаёт `admin` (администратор), `manager`, `operator`, `accountant` с паролями из `demo-accounts.txt` (нет файла — новые случайные) и печатает, где их взять.

### Task 6. Скрипты урока
- `setup.cmd` больше не просит `createsuperuser` — печатает учётные записи.
- `reset-demo.cmd` — свежая база с историей «на сегодня» (свежие заказы снова свежие, таймеры не просрочены); пароли прежние.
- `start.cmd` дожидается запуска и сам открывает витрину и админку.
- Сборка: у поля IMEI — подсказки. Свой склад — устройства с полки; товар поставщика в учебном режиме — готовый верный IMEI (ученик не придумает IMEI с контрольной цифрой).

### Task 7. Документация
- `docs/lesson.md` — как показать магазин на уроке: подготовка, сценарий по ролям, что сказать ученикам.
- README: сотрудники, сброс, урок. `docs/deploy.md`: сервер необязателен, показ с компьютера учителя; Oracle Cloud больше не рекомендуется первым.

### Task 8. Проверка и подготовка этого компьютера
- Полные тесты, e2e на отдельной базе, вход каждым сотрудником и скриншоты их страниц.
- На этом компьютере — `setup.cmd` начисто: `backend\.env`, база с историей, учётные записи; проверка `start.cmd`.
