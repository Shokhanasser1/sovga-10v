# Интернет-магазин электроники (Узбекистан) — дизайн-спецификация

- Дата: 2026-10-08
- Статус: разделы 2–7 согласованы с владельцем; разделы 8–9 (роудмап, риски) — на ревью
- Стек: Django 6.0 + DRF (бэкенд), Next.js / React (фронтенд)

## 1. Исходные данные

| Параметр | Решение |
|---|---|
| Регион | Узбекистан |
| Валюты | Закупка в USD, продажа и чек в UZS |
| Модель | Гибрид: собственный сток + посредничество (дропшиппинг со склада поставщика) |
| Поставщики | Все три типа: API / учётная система, Excel / Google Sheets, Telegram / вручную |
| Учёт | Система магазина — источник правды по товару, остаткам, IMEI. Бухгалтерия — отдельно, получает выгрузку реализаций |
| Отличие от конкурентов | Бесплатная доставка + подарок (чехол / стекло / зарядка) на выбор в пределах бюджета |
| IMEI и гарантия | Да, поштучный учёт для телефонов и планшетов |
| Рассрочка | Да, через партнёров (Uzum Nasiya / Alif Nasiya) |
| Архитектура | Модульный монолит (вариант A); Saleor и микросервисы отклонены |

**Допущения** (владелец может изменить):
- Масштаб: 2–5 тыс. SKU, до ~300 заказов/день, пики ×10 в распродажи.
- Языки витрины: русский и узбекский (латиница).
- Команда: 2 backend (Django), 2 frontend (Next.js), дизайнер (частично), QA (с нед. 6), владелец продукта; 2 контент-менеджера с нед. 3.

## 2. Модель каталога

### 2.1 Сущности

**Category** — `parent`, `slug`, `name{ru,uz}`, `is_serialized` (поштучный учёт по IMEI/SN: телефоны, планшеты — да; чехлы — нет).

**AttributeDefinition** — набор атрибутов категории (наследуется дочерними):
`code`, `name{ru,uz}`, `type` (number | enum | bool | text), `unit`, `enum_values`, `level` (model | variant), `is_variant_axis`, `is_facet`, `comparison` (higher_better | lower_better | none), `sort_order`.

**Brand** — `slug`, `name`.

**ProductModel** — «iPhone 16 Pro»: `category`, `brand`, `slug`, `name{ru,uz}`, `description{ru,uz}`, `attributes` (JSONB, атрибуты уровня model), SEO-поля, `is_accessory`, `status`.

**Variant (SKU)** — «256 ГБ · Desert Titanium · nano-SIM+eSIM · Global»:
`product_model`, `sku`, `barcodes[]`, `axes` (JSONB: память, цвет, SIM-конфигурация, регион), `attributes` (JSONB, уровень variant), `mxik_code` (ИКПУ, обязателен), `package_code` (обязателен), `weight`, `images[]`, `giftable`, `status`.

**Совместимость аксессуаров** — два вида:
- `AccessoryCompat(accessory_model, device_model)` — явная привязка (чехлы, стёкла);
- `CompatRule(accessory_model, rule)` — правило по характеристикам (зарядки, кабели), например `{"connector": "usb-c", "protocols": ["pd"], "min_watts_from": "max_charge_w"}`. Новое устройство получает совместимые зарядки без ручной привязки.

**GiftPolicy** — `scope` (категория / бренд / ценовой диапазон), `budget_pct_of_net_margin`, `budget_cap_uzs`, `priority`, `active_from`, `active_to`.

**CustomerDevice** (P1) — `customer`, `product_model` — «Мой телефон» для фильтра аксессуаров.

### 2.2 Ключевые решения

1. **Типизированный JSONB вместо EAV.** Схема атрибутов в `AttributeDefinition`, значения в JSONB, валидация при сохранении, GIN-индекс. Фасеты строятся в Meilisearch.
2. **Сравнение моделей** подсвечивает лучшее значение по `comparison` — без ручной разметки.
3. **Регион/версия — ось вариации** с предупреждением на карточке (например, eSIM-only у американских iPhone начиная с 14-й серии).
4. **Подарок — бюджет, а не товар.** Пул подарков: `giftable`-аксессуары на собственном складе, совместимые с купленной моделью.
5. Переводимые поля — `{ru, uz}`.

## 3. Источники, остатки, IMEI, цены

### 3.1 Сущности

- **Supplier** — контакты, `connector_type` (api | sheet | telegram), `ttl_hours`, `reliability_score`, условия оплаты.
- **SupplierFeedRun / SupplierFeedRow** — журнал импорта и сырые строки (`raw`, `supplier_code`, распарсенные имя/цена/кол-во, `match_status`).
- **SupplierSkuMap** — `(supplier, supplier_code) → variant`, уникально.
- **Warehouse** — собственные склады (на старте один).
- **Offer** — `variant`, `source_type` (own | supplier), `supplier`/`warehouse`, `cost_usd`, `qty_available`, `lead_time_days`, `condition` (new), `last_confirmed_at`, `is_active`.
- **InventoryUnit** — `variant`, `warehouse`, `imei1`, `imei2`, `serial`, `uzimei_status` (unknown | registered | not_registered), `purchase_batch`, `cost_usd`, `status` (in_stock | reserved | sold | returned | defective), `order_line`.
- **PurchaseBatch** — `supplier`, дата, курс, сумма USD.
- **Reservation** — `offer` или `unit`, `cart`/`order`, `qty`, `expires_at`, `kind` (hard — свой склад; soft — поставщик до подтверждения).
- **ExchangeRate** — `date`, `cbu_rate` (cbu.uz), `spread_pct`, `effective_rate`.
- **MarkupRule** — `scope`, `markup_pct`, `min_margin_uzs`, правило округления.
- **PriceSnapshot** — `variant`, `price_uzs`, `base_offer`, `cost_usd`, `rate`, `rule`, `computed_at`.

### 3.2 Правила

1. **Сопоставление прайсов.** Нераспознанная строка → очередь в админке с подсказками нечёткого поиска → после ручной привязки запись в `SupplierSkuMap`, далее автоматически.
2. **Свежесть остатков.** TTL по типу коннектора: API — 1 ч, таблица — 24 ч, Telegram — 6 ч. Просроченный остаток показывается как «под заказ, 1–2 дня», никогда как «в наличии».
3. **Маршрутизация.** Клиент видит одну цену на SKU. Порядок: свой склад → поставщик с лучшим баллом (цена + срок + надёжность). Если маржа ниже `min_margin_uzs` — алерт менеджеру.
4. **IMEI.** Для `is_serialized` категорий заказ нельзя перевести в «отправлен» без IMEI и отметки UzIMEI. Свой сток сканируется при приёмке; товар поставщика — при передаче через магазин или поставщик вводит IMEI в Telegram-боте. Проверка UzIMEI на старте ручная.
5. **Цена.** `price_uzs = round(cost_usd × effective_rate × (1 + markup))`. Пересчёт Celery-задачей при изменении курса > 0,5 % или закупки. Витрина и чек — только UZS; USD — в админке; справочная цена в $ — переключатель, включается только после подтверждения юриста.
6. **Резервы.** На чекауте 15 минут; резерв на товар поставщика — мягкий до подтверждения.

### 3.3 Telegram-бот

- Клиенты: вход по номеру, статусы заказа, позже Mini App.
- Поставщики без API: заказ с кнопками «Есть / Нет / Другая цена», ввод IMEI.
- Менеджеры: алерты (новый заказ, поставщик молчит 30 мин, маржа ниже порога).
- Токен хранится только в секретах сервера (`.env` / менеджер секретов), не в коде и не в git.

## 4. Архитектура

> **Решение 2026-10-08: без Docker.** Проект должен запускаться на обычном компьютере без Docker. Поэтому: база по умолчанию — SQLite (PostgreSQL подключается через `DATABASE_URL` при выходе в прод); Redis и Celery не используются — все фоновые задачи (прайсы поставщиков, курс ЦБ, пересчёт цен, снятие просроченных резервов, позже outbox и SLA-таймеры) выполняет команда `manage.py run_jobs`, запускаемая по расписанию (Планировщик заданий Windows или cron) раз в 15–30 минут. Везде ниже, где упомянуты Celery / Redis, читать «`run_jobs`» / «база данных». Celery и Redis вернутся, только если команда перестанет справляться с нагрузкой.

```
 Покупатели ─┬─ Next.js (SSR/ISR, ru/uz) ───┐
             └─ Telegram Mini App (P1) ─────┤
 Telegram-бот ──────────────────────────────┤        ┌─ PostgreSQL   основная БД
 Операторы ── Django Admin + 3 React-экрана ┤        ├─ Redis        кэш, резервы, брокер
                                            ▼        ├─ Meilisearch  поиск, фасеты
                     Django 6.0 + DRF (модульный) ─────┼─ S3 + CDN     фото
                                            │        └─ Celery       воркеры + beat
                                            ▼
   Адаптеры: Payme · Click · Uzum Nasiya / Alif Nasiya · доставка · курс ЦБ
             · OTP (Telegram Gateway → SMS Eskiz) · фискализация · UzIMEI · Yandex Maps
```

**Модули (Django-приложения):** `catalog`, `sourcing`, `inventory`, `pricing`, `promo` (подарки), `cart`, `orders`, `payments`, `installments`, `shipping`, `warranty`, `notifications`, `customers`. Межмодульное взаимодействие — только через сервисный слой модуля (`services.py`), без доступа к чужим таблицам.

**Интерфейсы адаптеров:** `PaymentProvider`, `InstallmentProvider`, `CarrierProvider`, `SupplierConnector`. Новый провайдер — новый адаптер, модуль заказов не меняется.

**Надёжность:**
- Outbox: события пишутся в `OutboxEvent` (`type`, `payload`, `status`, `attempts`, `next_attempt_at`) в той же транзакции, что и изменение заказа; Celery доставляет с повторами.
- Входящие вебхуки: проверка подписи (Payme — ключ мерчанта, Click — `sign_string`), идемпотентная обработка по внешнему ID транзакции.

**API и фронтенд:**
- REST (DRF) + OpenAPI (drf-spectacular) → сгенерированный TypeScript-клиент для Next.js.
- Карточки товаров — ISR + CDN; цена и наличие — отдельный лёгкий запрос на клиенте. При изменении цены — on-demand revalidation.
- Админка: Django Admin (тема Unfold) для каталога, поставщиков, настроек. Собственные React-экраны — только: рабочее место оператора, очередь сопоставления, сканирование IMEI.

**Местная специфика:**
- Вход по телефону: OTP через Telegram Gateway, при недоставке — SMS (Eskiz).
- Адрес: текст + ориентир + точка на Yandex Maps.
- Персональные данные граждан Узбекистана — на серверах в Узбекистане (БД и бэкенд в местном ДЦ); CDN для фото может быть зарубежным.

**Лимит запросов к публичному API (решение 2026-10-08).** Django считает запросы по посетителю: адрес берётся из `X-Real-IP` только от доверенного прокси (`TRUSTED_PROXIES`), `X-Forwarded-For` не используется — Next.js пробрасывает его от клиента как есть. Серверная отрисовка витрины освобождается от лимита только по общему секрету `INTERNAL_API_TOKEN` (в `backend/.env` и `frontend/.env`). Требования к проду: nginx отдаёт `/api/` напрямую в Django с `proxy_set_header X-Real-IP $remote_addr;`, остальное — в Next.js; `INTERNAL_API_TOKEN` задан в обоих приложениях. Без этого все посетители делят один счётчик (строго, но не обходится).

**Инфраструктура старта:** без Docker. Локально — `pip install -r requirements.txt`, SQLite, `runserver` и `run_jobs` по расписанию. В проде — 1–2 ВМ в Узбекистане, PostgreSQL с ежедневными бэкапами и WAL-архивом; Sentry, uptime-мониторинг, структурированные логи.

## 5. Жизненный цикл заказа

```
CREATED ─► SOURCING ─► CONFIRMED ─┬─► AWAITING_PAYMENT ─► PAID ──────┐
                                  ├─► INSTALLMENT_PENDING ─► SIGNED ─┤
                                  └─► COD ───────────────────────────┤
                                                                     ▼
   COMPLETED ◄─ DELIVERED ◄─ HANDED_TO_CARRIER ◄─ PICKING (IMEI + UzIMEI + подарок)
       │
       └─► RETURN_REQUESTED ─► INSPECTED ─► REFUNDED
   CANCELLED ← из любого состояния до HANDED_TO_CARRIER
```

### 5.1 Сущности

- **Customer** — `phone`, `telegram_id`, `language`. **Address** — текст, ориентир, `lat`, `lng`.
- **Cart / CartLine** — `variant`, `qty`, `gift_choice`.
- **Order** — `number`, `customer`, `status`, `channel` (web | miniapp), `payment_method` (card | installment | cod), `address`, `total_uzs`, `rate_snapshot`, `price_lock_until`, `sla_deadline`.
- **OrderLine** — `variant`, `qty`, `price_uzs`, `cost_usd`, `offer`, `inventory_unit`, `is_gift`, `gift_for_line`.
- **Payment** — `provider`, `external_id`, `amount_uzs`, `status`, сырые колбэки.
- **InstallmentApplication** — `provider`, `term_months`, `monthly_uzs`, `status`, `contract_id`.
- **Shipment** — `carrier`, `tracking`, `status`, `cost_uzs`.
- **ReturnRequest** — `order_line`, `reason`, `imei_received`, `inspection_result`, `refund_amount_uzs`, `gift_returned`.
- **WarrantyCase** — `inventory_unit` / IMEI, описание, сервисный центр, `status`.

### 5.2 Правила

**Момент оплаты:**
- Свой склад или поставщик с API и свежим остатком → CONFIRMED сразу, оплата на чекауте; при отказе поставщика — автовозврат (Payme `CancelTransaction`, отмена платежа Click).
- Поставщик через Telegram / таблицу → заказ без оплаты → подтверждение поставщика (цель ≤ 30 мин в рабочее время) → ссылка на оплату в бот / SMS.
- COD (оплата при получении) — входит в MVP только если выбранная служба доставки выдаёт фискальный чек при выдаче; иначе переносится в P2.

**Рассрочка:**
1. Калькулятор 3 / 6 / 12 мес. на карточке по тарифам провайдера.
2. Идентификация и лимит — на стороне провайдера; при отказе — другой провайдер или карта, корзина сохраняется.
3. Договор подписан (SIGNED) → сборка → после доставки подтверждение выдачи провайдеру → провайдер перечисляет сумму за вычетом комиссии → сверка Celery-задачей.
4. Бюджет подарка считается от чистой маржи после комиссии провайдера.

**Подарок:**
- Строка заказа с ценой 0, `is_gift = true`, ссылка на основную строку; себестоимость фиксируется.
- Резерв на чекауте. Нет в наличии при сборке → автозамена совместимым аксессуаром равной или большей стоимости + уведомление клиента.
- Возврат основного товара → подарок возвращается или его стоимость удерживается (правило в публичной оферте).

**Возвраты и гарантия:**
- Отмена до отгрузки: снятие резервов, автовозврат, отзыв заявки на рассрочку.
- Приёмка возврата: IMEI сверяется с проданным; несовпадение — отказ.
- Гарантийный случай открывается по IMEI: дата покупки, поставщик, срок гарантии, сервисный центр.

**Сбои:**

| Ситуация | Реакция |
|---|---|
| Поставщик не ответил 30 мин | Алерт менеджеру; через 2 ч — следующий поставщик или отмена с извинением |
| Поставщик отказал | Автопоиск другого; если дороже — проверка `min_margin_uzs`, при нарушении решает менеджер |
| Оплата пришла после отмены / истечения | Автовозврат + алерт |
| Курс изменился во время чекаута | Цена фиксируется на 30 мин с создания заказа (`price_lock_until`), затем пересчёт |
| API доставки недоступен | Повторы через outbox; ручное создание накладной в админке |

Все таймеры — задачи Celery beat, значения настраиваются в админке.

## 6. MVP

### P0 — витрина
- Поиск с автокомплитом, опечатками, транслитерацией ru/uz/lat (синонимы: «aypon», «айфон» → iPhone).
- Каталог с фасетами: бренд, память, цена, цвет, SIM / регион, наличие.
- Карточка: матрица вариаций (недоступные — серые), срок «в наличии» / «под заказ», предупреждение eSIM-only / регион, калькулятор рассрочки, выбор подарка.
- Сравнение моделей с подсветкой лучшего значения.
- Корзина (гостевая, сливается после входа).
- Быстрый чекаут на одном экране: телефон + OTP → адрес с картой → оплата; «Купить сейчас» с предзаполнением для вернувшегося клиента.
- Payme + Click с фискализацией; рассрочка — один провайдер (первый подписанный).
- Личный кабинет: заказы, статусы, гарантия по IMEI.
- ru/uz, SSR, sitemap, schema.org Product, ЧПУ.

### P0 — операции
- Каталог, атрибуты, совместимость, GiftPolicy в Django Admin.
- Коннекторы: Excel/Sheets, API (один ключевой поставщик), Telegram-бот; очередь сопоставления.
- Рабочее место оператора с SLA-таймерами.
- Приёмка / сборка: скан IMEI, отметка UzIMEI, подарок.
- Курс ЦБ, пересчёт цен, алерт маржи.
- Доставка: одна служба + ручной режим для своих курьеров по Ташкенту.
- Уведомления Telegram (SMS — резерв); выгрузка реализаций для бухгалтера (Excel/CSV).

### P1 — месяцы 5–6
Telegram Mini App; «Мой телефон»; заказ в 1 клик по сохранённой карте (токенизация Payme); второй провайдер рассрочки и вторая служба доставки; самообслуживание возвратов (RMA) в кабинете; отзывы.

### P2 — по данным
Веб-кабинет поставщика; автоматическая проверка UzIMEI (при наличии доступа к API); лояльность; рекомендации; COD (если не вошёл в MVP).

### Не делаем
Нативные приложения (заменяются Mini App + PWA), микросервисы, мультивендорный маркетплейс с выплатами, собственное кредитование.

## 7. Тестирование

- **Property-based (Hypothesis)** для денег: цена при любом курсе и правиле ≥ себестоимость + минимальная маржа; бюджет подарка ≤ его доля маржи.
- **Машина состояний заказа:** каждый разрешённый переход и невозможность запрещённых.
- **Платёжные адаптеры:** песочницы Payme / Click; контрактные тесты на записанных колбэках, включая повторные и неподписанные.
- **E2E (Playwright):** поиск → вариант → подарок → чекаут → оплата в песочнице.
- **Нагрузка (k6):** ×10 к пиковой нагрузке перед запуском.

## 9. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Затяжное подключение рассрочки / эквайринга | Высокая | Высокое | Заявки в нед. 0; флаг запуска без рассрочки |
| Незарегистрированный IMEI от поставщика (UzIMEI) | Средняя | Критичное | Без проверки отгрузка невозможна; ответственность в договоре; рейтинг поставщика |
| Устаревшие остатки поставщиков → отмены | Высокая | Среднее | TTL, статус «под заказ», подтверждение до оплаты, рейтинг надёжности |
| Подарок + бесплатная доставка съедают маржу | Средняя | Высокое | Бюджет от чистой маржи; отчёт юнит-экономики по заказу с первого дня; при необходимости — порог суммы для бесплатной доставки |
| Валютный риск (курс сума) | Средняя | Среднее | Спред к курсу ЦБ, пересчёт по порогу, фиксация курса в заказе |
| Регуляторика: валюта на витрине, ПДн, фискализация подарков и COD | Средняя | Высокое | Юрист в фазе 0, хостинг в УЗ |
| Наполнение каталога не успевает | Высокая | Сроки | Топ-300 SKU на старте, шаблоны атрибутов, импорт характеристик |
| Мошенничество: подмена устройства при возврате, фейковые COD-заказы | Средняя | Среднее | Сверка IMEI при возврате, OTP, лимиты COD |
| Зависимость от одного поставщика | Средняя | Высокое | ≥ 2 поставщика на топ-SKU |
| Утечка секретов | Средняя | Высокое | Секреты только в менеджере секретов / `.env` на сервере; ротация при утечке |
