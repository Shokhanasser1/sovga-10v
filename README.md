# Sovgʻa — интернет-магазин электроники для Узбекистана

Смартфоны и техника с бесплатной доставкой и подарком на выбор (чехол, стекло, зарядка). Свой склад и товар поставщиков под заказ, цены в сумах по курсу ЦБ, оплата Payme и Click, учёт IMEI и гарантия, Telegram-бот для покупателей, поставщиков и менеджеров.

| Часть | Технологии | Где |
|---|---|---|
| API, админка, рабочее место оператора, бот | Python, Django 6, DRF | `backend/` |
| Витрина ru/uz | Next.js 16, React 19, TypeScript | `frontend/` |
| Проверка в браузере | Python Playwright | `e2e/` |
| Спецификация и планы | — | `docs/superpowers/` |
| Запуск на сервере | nginx, gunicorn, systemd, cron | `docs/deploy.md`, `deploy/` |

Docker не нужен: база по умолчанию SQLite, фоновые задачи — команда `run_jobs` по расписанию.

Проект открытый и учебный (лицензия [MIT](LICENSE)): его можно запускать, менять и развивать — с чего начать, написано в [CONTRIBUTING.md](CONTRIBUTING.md).

## Учебный режим — без единого ключа

По умолчанию (`DEMO_MODE=true` в `backend\.env`) всё, для чего нужны ключи, имитируется — но работает тот же код, что с настоящими сервисами:

- **Код входа** показывается на странице входа и подставляется сам.
- **Оплата Payme и Click** — страница «Учебная оплата»: магазин получает те же запросы, что прислал бы настоящий провайдер. Можно оплатить, отказаться или «вернуть деньги».
- **Telegram-бот** — админка → «Имитация Telegram»: сообщения бота поставщикам, покупателям и менеджерам, кнопки «Есть / Нет / Другая цена», ответы от имени любого чата.
- **Оплата при получении** — покупатель выбирает её при оформлении: заказ сразу идёт на сборку, курьер берёт деньги при выдаче.
- **Сотрудники** — `setup.cmd` создаёт администратора, менеджера, оператора и бухгалтера, у каждого свои права. Логины и пароли — в `backend\demo-accounts.txt` (в git не попадает).

Настоящий ключ в `.env` всегда главнее имитации. Для настоящего магазина — `DEMO_MODE=false` и ключи.

**Демо-данные.** `setup.cmd` (команда `seed_demo`) наполняет магазин: 66 товаров в 8 категориях с описаниями на русском и узбекском, свой склад с IMEI, поставщики, наценки и подарки. В учебном режиме добавляется история за полтора месяца: 12 покупателей, 31 заказ во всех статусах (Payme, Click и оплата при получении), возвраты, гарантийные случаи, отчёт для бухгалтера и переписка в «Имитации Telegram». Магазин глазами покупателя — войдите на витрине по номеру `90 111 01 01` (до `90 111 01 12`): код покажется на экране.

## Запуск на Windows

Нужны [Python 3.12+](https://www.python.org/downloads/) (при установке — галочка «Add python.exe to PATH») и [Node.js 20+](https://nodejs.org/).

```
scripts\setup.cmd        один раз
scripts\reset-demo.cmd   перед уроком — магазин как новый
scripts\start.cmd        каждый раз
```

- `setup.cmd` — один раз: зависимости, `backend\.env` со своим секретным ключом, база, демо-каталог, сотрудники, сборка витрины. Логины и пароли печатает в конце.
- `reset-demo.cmd` — свежая база учебного магазина: история «на сегодня», пароли прежние. Только при `DEMO_MODE=true` и базе SQLite.
- `start.cmd` — каждый раз: открывает окна API, витрины и (если в `backend\.env` есть токен) бота, потом сам открывает витрину и админку в браузере.
- Как показать магазин на уроке — сценарий по ролям и что делать, если что-то пошло не так: [docs/lesson.md](docs/lesson.md).
- Витрина — http://localhost:3000, админка — http://localhost:8000/admin, рабочее место оператора — в меню админки.
- Код входа в учебном режиме — на странице входа (без учебного режима и без ключей — в окне «Sovga — API»).
- Фоновые задачи (прайсы, курс ЦБ, цены, просрочки, уведомления): вручную — `scripts\jobs.cmd`; по расписанию каждые 15 минут —
  `schtasks /create /tn "Sovga run_jobs" /sc minute /mo 15 /tr "\"C:\путь\к\проекту\scripts\jobs.cmd\""`.
- Разработка витрины с мгновенным обновлением: в `frontend` — `npm run dev` вместо окна витрины.

## Настройки

- `backend\.env` — по образцу `backend\.env.example`: база, ключи Payme / Click, коды входа, Telegram-бот, лимиты, срок возврата.
- `frontend\.env.local` — по образцу `frontend\.env.example`: адреса API и витрины.
- Секреты — только в этих файлах; в git они не попадают.
- Роли сотрудников — группы «Менеджер», «Оператор», «Бухгалтер». Настоящему магазину (`DEMO_MODE=false`) готовых учётных записей нет: администратор — `manage.py createsuperuser`, остальным в админке → «Пользователи» ставится «Статус персонала» и группа.

## Проверки

```
cd backend
.venv\Scripts\python.exe -m pytest            # бэкенд
cd ..\frontend
npm test                                       # фронтенд
npx tsc --noEmit
npm run lint
```

Сквозная проверка в браузере — покупка от поиска до оплаты и возврата (нужны `pip install playwright` и `playwright install chromium`): запустите `scripts\start.cmd` (учебный режим, ключи не нужны) и выполните `python e2e\storefront_check.py`.

## Боевой запуск

Для урока сервер не нужен — магазин работает на компьютере учителя. Чтобы магазин открывался из интернета, нужен сервер с Ubuntu — пошагово в [docs/deploy.md](docs/deploy.md): HTTPS, службы, расписание, копии базы, кабинеты Payme и Click.
